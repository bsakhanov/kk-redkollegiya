# Пайдалану нұсқаулығы

[Русский](USAGE.md) · [English](USAGE.en.md) · **Қазақша** · [← README](../README.kk.md)

Нұсқаулық орнатудан бастап бес типтік тапсырмаға дейін жетелейді. Ереже кодтары мен глоссарий өрістері — [RULES.kk.md](RULES.kk.md) ішінде.

## 1. Не қажет

- Python 3.8 немесе одан кейінгі версиясы.
- `pip install -r requirements.txt` — `spylls` (сөздік қозғалтқышы) пен `pyyaml` (глоссарийлер мен тізімдер) орнатады.
- hunspell-kk сөздігі. `sh tools/fetch_hunspell_kk.sh` `kk_KZ.aff` және `kk_KZ.dic` файлдарын `data/hunspell/` каталогына салады. Windows жүйесінде
  скрипт жұмыс істемейді: `hunspell-kk` пакетін жүктеп алыңыз (`.deb` мекенжайы скрипттің ішінде), одан `data.tar.xz` архивін ашып, екі файлды да
  `usr/share/hunspell/` ішінен `data/hunspell/` каталогына көшіріңіз. Сөздіксіз алфавитті тазалау, типографика және сандарды тексеру жұмыс істейді,
  ал сөздерді тексеру жұмыс істемейді.
- Мәтіндер UTF-8 кодтауында болуы керек. PDF-тен мәтінді `pdftotext -enc UTF-8 book.pdf book.txt` командасымен, EPUB-тан pandoc арқылы алады.
- Қалауыңызша — [redkollegiya](https://github.com/beaverbeard/redkollegiya) жобасындағы `apply.py`: ол табылған түзетулерді дәйексөз бойынша мәтінге енгізеді.

Орнатуды тексеру: `sh tests/run_tests.sh` қатесіз аяқталуы керек, ал `python3 tools/kk_lint.py --version` версияны шығаруы керек.

## 2. Нәтижені қалай оқу керек

`kk_lint.py` мен `kk_parity.py` ескертулерді (findings) JSON түрінде жазады (`--json файл`). Бір ескерту (`note` өрісінің мәтінін құрал орысша жазады):

```json
{"id": "T01-0001", "stage": "kk_lint", "zone": "terms", "layer": "shakarim", "severity": "fix",
 "rule": "T01 ru_abbrev", "quote": "РК", "action": "apply", "edit": "ҚР",
 "note": "в казахском тексте «ҚР» вместо «РК»"}
```

- `quote` — мәтіннен алынған сөзбе-сөз үзінді, бірегей болғанша кеңейтілген; `edit` — ауыстыру енгізілген сол үзінді.
- `severity`: `blocker` — жариялауға болмайды; `fix` — мәтінге енгізіледі; `author_choice` — шешімді адам қабылдайды.
- `action`: `apply` — енгізу; `suggest` — ауыстыруды ұсыну; `flag` — ауыстыру жоқ.
- `layer` — ескерту жататын есімі бар қабат: `altynsarin`, `valikhanov`, `shakarim`, `baitursynov` ([RULES.kk.md](RULES.kk.md) қараңыз).
- `kk_lint.py` қайтару коды: 0 — жақсы, 1 — енгізу қатесі, 2 — `blocker` деңгейіндегі ескерту бар.

Ескертулерді redkollegiya-дағы `apply.py` енгізеді: ол `apply` әрекеті бар ескертулерді қолданады, қалғанын авторға қалдырады (оның есебінде бұл
`to_author` тізімі). Скрипттердің өзі мәтінді қайта жазбайды.

## 3. A тапсырмасы. Кітапты немесе PDF экспортын ретке келтіру

```bash
python3 tools/kk_clean.py books/*.txt -o clean/ --dict data/hunspell/kk_KZ --journal journal.json
```

Әр файл үшін `book.txt: legacy:494672, homoglyph:10` сияқты жол шығады: кезең және түзетулер саны. `journal.json` санауыштар мен «бұрын → кейін» мысалдарын сақтайды.

| Кезең | Нені түзетеді |
| --- | --- |
| `nfc` | бөлшектенген таңбалар («й», «ё» екі белгіден тұрады) |
| `legacy` | қазақ шрифттерінің ескі кодтауы; өзі анықталады («мектеп» сөзі «ìåêòåï» болып оқылады) |
| `schwa` | «ә» орнына латын «ə»; «ә ө ү» орнына «ӓ ӧ ӱ» |
| `substitute` | қазақ әріптерінің орнындағы басқарушы және латын таңбалары; сөздік қажет. `substitute_guess` жазбасы — сөздік растамаған сөздер: оларды журналдан қарап шығыңыз |
| `homoglyph` | кириллицамен жазылған сөздердің ішіндегі ұқсас латын әріптері («қорықca») және керісінше («ІSBN»); `homoglyph_ambiguous` — шешілмеген |
| `dehyphenate` | тек `--dehyphenate` болса: жол соңындағы сызықшамен бөлінген сөзді, нәтиже сөздікте бар болса, біріктіреді. «-», «¬» белгілері және жұмсақ тасымал бірдей түсініледі |
| `ocr` | тек `--ocr` болса: кітапты танудан кейінгі «ү» мен «ұ» шатасуы («жүмыс» → «жұмыс»). Сөз сөздікте жоқ болса және «ұ» нұсқасы сөздікте бар болса, не «ү» артқы қатар дауыстыларының қасында тұрса (қазақ сөзінде олай болмайды), түзетіледі; журнал жазбалары `ocr` және `ocr_harmony`. `--lm модель` (`kk_restore.py train` үйреткен) берілсе, қадам жоғалған қазақ әріптерін де түзетеді («кызметімен» → «қызметімен»): сөз сөздікте жоқ болса, модель 2,0 айырмамен нұсқа ұсынса және ол нұсқа сөздікте бар болса ғана түзетіледі; жазба `ocr_lm`. Екіұшты жағдай («кол» — «қол» не «көл») түзетілмейді |

`--check` ештеңе жазбайды, тек журналды көрсетеді. `--no-legacy` ескі кодтауды анықтауды өшіреді. Екі тілді басылымдарды (қазақша және орысша мәтін
араласқан) кез келген санаудан бұрын орыс жолдарынан бөлек тазалаңыз.

**DjVu-дағы кітап немесе скан.** DjVu-дың мәтін қабатын `djvutxt book.djvu book.txt` алады. Қабат жоқ болса немесе бүлінсе (мысалы, онда бірде-бір қазақ әрпі жоқ), беттерді қайта тану керек: `ddjvu -format=pgm -page=7 book.djvu page.pgm`, содан кейін `tesseract page.pgm page -l kaz+rus --psm 3`. Қазақ моделі `kaz.traineddata` tessdata_fast жинағынан алынады. Танылған мәтінді `kk_clean.py --dehyphenate --ocr --lm lm.json.gz` арқылы өткізіңіз: тану құралдары «ү» мен «ұ» әріптерін жиі шатастырады, қазақ әріптерін жоғалтады және жол соңындағы сызықшаларды қалдырады.

## 4. B тапсырмасы. Мақаланы немесе сайт бетін тексеру

```bash
python3 tools/kk_lint.py clean/article.txt --dict data/hunspell/kk_KZ --glossary data/glossary.yaml \
        --json findings.json --unknown-tsv unknown.tsv
python3 /path/to/apply.py --text clean/article.txt --findings findings.json --out article_v2.txt --report report.json
```

1. Бірінші команда жиынтық шығарады: әр ереже мен деңгей бойынша қанша ескерту бар.
2. Екінші команда `apply` әрекеті бар `fix` ескертулерін енгізеді және есеп жазады: `applied` — енгізілгені, `to_author` — шешім күтетіні.
3. `suggest` және `flag` ескертулерін `findings.json` ішінен (`quote`, `edit`, `note` өрістері) қарап, мәтінді қолмен түзетіңіз.

**Сөздікте жоқ сөздер.** `unknown.tsv` (сөз және кездесу саны) — ақ тізімге ұсынылатын сөздер. Дұрыс сөздерді (есімдер, терминдер) `whitelist.txt` файлына
әр жолға біреуден қосып, `--whitelist whitelist.txt` опциясымен іске қосыңыз: артық ескертулер азаяды.

**Қазақ әріптерін қалпына келтіру.** Мәтінде «Қазақстан» орнына «Казакстан» кездессе, модельді өз таза корпусыңызда үйретіп, қосыңыз:

```bash
python3 tools/kk_restore.py train clean/*.txt -o lm.json.gz
python3 tools/kk_lint.py text.txt --dict data/hunspell/kk_KZ --lm lm.json.gz --json findings.json
```

S01 ережесі «Казакстан» → «Қазақстан» түзетуін `suggest` ретінде ұсынады. `--auto-restore` опциясы сенімділігі жоғары ұсыныстарды енгізеді: оны тек
қазақ әріптерінсіз толық терілген мәтінге ғана пайдаланыңыз. Сөйлем ішіндегі бас әріппен жазылған сөздер есім ретінде өткізіліп жіберіледі;
`--names` оларды да тексеруді қосады. Модельдің сіздің мәліметтеріңіздегі сапасын `kk_restore.py eval --lm lm.json.gz --test book.txt` тексереді.

**Ережелерді таңдау:** `--only H01,H02` тек аталғандарды іске қосады, `--skip P02` аталғандарды өткізіп жібереді.

## 5. C тапсырмасы. Joomla тіл бумасы (.ini)

```bash
python3 tools/kk_lint.py kk-KZ.com_example.ini --profile ini --source en-GB.com_example.ini \
        --dict data/hunspell/kk_KZ --json findings.json
```

`ini` профилінде тек тырнақшадағы мәндер тексеріледі: толтырғыштарға (`%s`, `%1$s`, `{name}`), тегтер мен `&nbsp;` сияқты HTML-таңбаларға тиіспейді.
Жоғалған немесе артық толтырғыш — `blocker` (J01) және қайтару коды 2; аударылмаған кілт — J02; `KEY="мән"` түрінде емес жол — J03.
Осылайша тексеруді құрастыруға қосуға болады:

```sh
for f in language/kk-KZ/*.ini; do
  src="language/en-GB/$(basename "$f" | sed 's/^kk-KZ/en-GB/')"
  python3 tools/kk_lint.py "$f" --profile ini --source "$src" --dict data/hunspell/kk_KZ || exit 1
done
```

## 6. D тапсырмасы. Аударманы орыс түпнұсқасымен салыстыру

```bash
python3 tools/kk_parity.py --ru original.md --kk kazakh.md --glossary data/glossary.yaml --json parity.json
```

Екі файлдағы абзацтар бос жолмен бөлінеді. Абзац саны сәйкес келмесе, бұл PR01, ал сандар бүкіл құжат бойынша салыстырылады.

| Код | Мағынасы | Не істеу керек |
| --- | --- | --- |
| PR02 (`blocker`) | абзацта бірдей санда сан жоғалып, қосылған: «15,3» орнына «15,8» шықты | түпнұсқамен салыстырып, түзету |
| PR03 | түпнұсқадағы сан қазақша нұсқада табылмады | тексеру: сөзбен жазылған болуы мүмкін |
| PR04 | қазақша нұсқада артық сан бар | тексеру: өлшем бірліктерін қайта есептеу болуы мүмкін |
| PR05 | латын атауы немесе қысқарту жоғалды | қайтару немесе саналы түрде ауыстыру |
| PR06 | түпнұсқада глоссарий ұғымы бар, ал таңдалған қазақ формасы жоқ | шешімді автор қабылдайды (тек `--glossary` болса) |

Сандар бір түрге келтіріледі: «6 мың» = «6000», «1,5 млрд» = «1 500 000 000», «12 желтоқсан» = «12 декабря» = «12.12.2025». Сөзбен жазылған сандар салыстырылмайды.

## 7. E тапсырмасы. Терминдер корпус қолданысы бойынша

Ереже: **корпус қолданысы бірінші; халықаралық сөз — қолданыс болмаған жерде ғана**. Топтар файлын дайындаңыз: кілті — корпус тобы,
жолдар файлдың өзінен есептеледі:

```yaml
# groups.yaml
corporate:
  label: корпоративтік қолданыс
  files: [corpus/news_kk.txt, corpus/channel_kk.txt]
```

```bash
# әр форма қанша рет кездеседі (контекстер мағыналарды ажыратуға көмектеседі)
python3 tools/kk_attest.py --groups groups.yaml --terms data/terms_variants.yaml --context 3

# жұптар бойынша шешімдер; глоссарийдегі автор шешімдері сақталады
python3 tools/kk_usage.py --groups groups.yaml --group corporate --pairs data/term_pairs.yaml \
        --merge data/glossary.yaml --out data/glossary.yaml --tsv decisions.tsv
```

Өз жұбыңызды `data/term_pairs.yaml` файлына қосыңыз: `a` — қазақша мәтіндегі халықаралық форма, `b` — қазақ формасы, `re` — кіші әріптерге арналған
тұрақты өрнек, `parity_ru` — ұғымның орыс түпнұсқасында қандай көрінетіні:

```yaml
- {key: well, ru: скважина, a: {label: скважина, re: "скважин\\w*"}, b: {label: ұңғыма, re: "ұңғыма\\w*"}, parity_ru: "скважин\\w*"}
```

Жазба мәртебелері: `usage` — бір форма кездесулердің кемінде 70% құрайды, жалпы саны он немесе одан көп; `silent` — кездесу онға жетпейді, халықаралық форма алынады;
`contested` — үлестер 30–70% аралығында, шешімді автор қабылдайды. Өз шешіміңізді бекіту үшін `status` өрісін өшіріңіз немесе `status: author` деп жазыңыз:
мұндай жазба `--merge` кезінде қайта жазылмайды. Линтер шешімдерді ұсыныс (`author_choice`) ретінде қолданады.

**Екі тілді Telegram-арнадан корпус.** Telegram Desktop ішінде «Чат тарихын экспорттау» әрекетін JSON форматымен таңдаңыз (`result.json` файлы):

```bash
python3 tools/kk_pairs.py build result.json -o pairs.jsonl                 # «қазақша жазба — орысша жазба» жұптары
python3 tools/kk_pairs.py align pairs.jsonl -o candidates.tsv              # екі тілді глоссарийге ұсынылатын жұптар
python3 tools/kk_pairs.py consistency pairs.jsonl --glossary data/glossary.yaml \
        --term-pairs data/term_pairs.yaml -o consistency.tsv --write       # аудармалар глоссарийді қаншалықты ұстанады
```

`candidates.tsv` — бірге кездесу статистикасы, сөздік емес: әр жұп бойынша шешімді адам қабылдайды. `--write` глоссарийге `consistency` және `parity_check` өрістерін
жазады; PR06 тексеруі үйлесімділігі кемінде 85% жазбалар үшін ғана қосылады.

## 8. Жиі кездесетін мәселелер

| Белгі | Не істеу керек |
| --- | --- |
| PyYAML туралы хабар немесе `spylls` табылмайды | `pip install -r requirements.txt` |
| «сөздік жүктелмеді» | `--dict` жолын `kk_KZ` атауына дейін жазыңыз (`data/hunspell/kk_KZ`), `.aff` және `.dic` қоспаңыз; бұл екі файл жанында тұруы керек |
| «ескі кодтауға ұқсайды» | алдымен мәтінді `kk_clean.py` арқылы өткізіңіз |
| сөздікте жоқ сөздер тым көп | дұрыс сөздерді `--whitelist` тізіміне қосыңыз; сөздік ескі, жаңа сөздерді білмейді |
| `apply.py` ескертуді авторға қайтарды: «дәйексөз бірегей емес» немесе «табылмады» | `quote` өрісі бойынша қолмен түзетіңіз; түзеткеннен кейін ескертулерді жаңа мәтінмен қайта салыстыру керек |
| қазақша мәтіндегі латын жазуы түзетілмейді | бұл әдейі: жиынтық кириллицаға арналған, латын сөздерге тиіспейді |
| мәтін UTF-8 емес | қайта кодтаңыз: `iconv -f cp1251 -t utf-8 in.txt > out.txt` |

Қателер мен тілектер — [Issues](https://github.com/bsakhanov/kk-redkollegiya/issues) бөлімінде.
