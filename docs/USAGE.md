# Руководство пользователя

**Русский** · [English](USAGE.en.md) · [Қазақша](USAGE.kk.md) · [← README](../README.md)

Руководство ведёт от установки к пяти типовым задачам. Коды правил и поля глоссария — в [RULES.md](RULES.md).

## 1. Что нужно

- Python 3.8 или новее.
- `pip install -r requirements.txt` — ставит `spylls` (движок словаря) и `pyyaml` (глоссарии и списки).
- Словарь hunspell-kk. `sh tools/fetch_hunspell_kk.sh` кладёт `kk_KZ.aff` и `kk_KZ.dic` в `data/hunspell/`. На Windows скрипт не
  запустится: скачайте пакет `hunspell-kk` (адрес `.deb` указан в скрипте), распакуйте из него `data.tar.xz` и скопируйте оба файла
  из `usr/share/hunspell/` в `data/hunspell/`. Без словаря работают чистка алфавита, типографика и числа, но не проверка слов.
- Тексты в UTF-8. Из PDF текст достаётся командой `pdftotext -enc UTF-8 book.pdf book.txt`, из EPUB — через pandoc.
- По желанию — `apply.py` из [redkollegiya](https://github.com/beaverbeard/redkollegiya): он вносит найденные правки по дословным цитатам.

Проверка установки: `sh tests/run_tests.sh` должен закончиться без ошибок, а `python3 tools/kk_lint.py --version` — напечатать версию.

## 2. Как читать результат

`kk_lint.py` и `kk_parity.py` пишут находки в JSON (`--json файл`). Одна находка:

```json
{"id": "T01-0001", "stage": "kk_lint", "zone": "terms", "severity": "fix",
 "rule": "T01 ru_abbrev", "quote": "РК", "action": "apply", "edit": "ҚР",
 "note": "в казахском тексте «ҚР» вместо «РК»"}
```

- `quote` — дословный фрагмент текста, расширенный до уникального; `edit` — этот фрагмент с уже внесённой заменой.
- `severity`: `blocker` — публиковать нельзя; `fix` — вносится в текст; `author_choice` — решает человек.
- `action`: `apply` — внести; `suggest` — предложить замену; `flag` — замены нет.
- Код возврата `kk_lint.py`: 0 — нормально, 1 — ошибка входа, 2 — есть находка уровня `blocker`.

Находки вносит `apply.py` из redkollegiya: он применяет находки с действием `apply`, а остальное оставляет автору (в его отчёте это
список `to_author`). Сами скрипты текст не переписывают.

## 3. Задача A. Привести в порядок книгу или выгрузку из PDF

```bash
python3 tools/kk_clean.py books/*.txt -o clean/ --dict data/hunspell/kk_KZ --journal journal.json
```

Для каждого файла печатается строка вида `book.txt: legacy:494672, homoglyph:10` — шаг и число правок. Журнал `journal.json` хранит
счётчики и примеры «было → стало».

| Шаг | Что чинит |
| --- | --- |
| `nfc` | разложенные символы («й», «ё» из двух знаков) |
| `legacy` | старая кодировка казахских шрифтов; определяется сама (слово «мектеп» читается как «ìåêòåï») |
| `schwa` | латинская «ə» вместо «ә»; «ӓ ӧ ӱ» вместо «ә ө ү» |
| `substitute` | управляющие и латинские символы вместо казахских букв; нужен словарь. Запись `substitute_guess` — слова, которых словарь не подтвердил: просмотрите их в журнале |
| `homoglyph` | латинские двойники внутри кириллических слов («қорықca») и наоборот («ІSBN»); `homoglyph_ambiguous` — не разобрано |
| `dehyphenate` | только с `--dehyphenate`: склеивает «слово-» и «продолжение» с переноса, если результат есть в словаре |

`--check` ничего не записывает и показывает только журнал. `--no-legacy` отключает определение старой кодировки.
Двуязычные издания (казахский и русский текст вперемешку) перед подсчётами очищайте от русских строк отдельно.

## 4. Задача B. Проверить статью или страницу сайта

```bash
python3 tools/kk_lint.py clean/article.txt --dict data/hunspell/kk_KZ --glossary data/glossary.yaml \
        --json findings.json --unknown-tsv unknown.tsv
python3 /path/to/apply.py --text clean/article.txt --findings findings.json --out article_v2.txt --report report.json
```

1. Первая команда печатает сводку: сколько находок каждого правила и какого уровня.
2. Вторая вносит `fix` с действием `apply` и пишет отчёт: `applied` — что внесено, `to_author` — что ждёт решения.
3. Находки `suggest` и `flag` просмотрите в `findings.json` (поля `quote`, `edit`, `note`) и поправьте текст вручную.

**Слова вне словаря.** Файл `unknown.tsv` (слово и число вхождений) — кандидаты в белый список. Верные слова (имена, термины) добавьте по одному
в строке в `whitelist.txt` и запускайте с `--whitelist whitelist.txt`: шум падает.

**Восстановление казахских букв.** Если в тексте встречается «Казакстан» вместо «Қазақстан», обучите модель на своём чистом корпусе и
подключите её:

```bash
python3 tools/kk_restore.py train clean/*.txt -o lm.json.gz
python3 tools/kk_lint.py text.txt --dict data/hunspell/kk_KZ --lm lm.json.gz --json findings.json
```

Правило S01 предложит «Казакстан» → «Қазақстан» как `suggest`. Флаг `--auto-restore` вносит подсказки с большим запасом уверенности —
используйте его только для текста, набранного целиком без казахских букв. Слова с прописной буквы внутри предложения пропускаются как имена;
`--names` включает их проверку. Качество модели на ваших данных проверяет `kk_restore.py eval --lm lm.json.gz --test книга.txt`.

**Выбор правил:** `--only H01,H02` запускает только перечисленные, `--skip P02` пропускает указанные.

## 5. Задача C. Языковой пакет Joomla (.ini)

```bash
python3 tools/kk_lint.py kk-KZ.com_example.ini --profile ini --source en-GB.com_example.ini \
        --dict data/hunspell/kk_KZ --json findings.json
```

В профиле `ini` проверяются только значения в кавычках: заполнители (`%s`, `%1$s`, `{name}`), теги и сущности (`&nbsp;`) не трогаются.
Потерянный или лишний заполнитель — `blocker` (J01) и код возврата 2; непереведённый ключ — J02; строка не вида `KEY="значение"` — J03.
Так проверку можно поставить в сборку:

```sh
for f in language/kk-KZ/*.ini; do
  src="language/en-GB/$(basename "$f" | sed 's/^kk-KZ/en-GB/')"
  python3 tools/kk_lint.py "$f" --profile ini --source "$src" --dict data/hunspell/kk_KZ || exit 1
done
```

## 6. Задача D. Сверить перевод с русским оригиналом

```bash
python3 tools/kk_parity.py --ru original.md --kk kazakh.md --glossary data/glossary.yaml --json parity.json
```

Абзацы в обоих файлах разделены пустой строкой. Если число абзацев не совпало, это PR01, а числа сверяются по документу целиком.

| Код | Что значит | Что делать |
| --- | --- | --- |
| PR02 (`blocker`) | в абзаце потеряно и добавлено поровну чисел: «15,3» стало «15,8» | сверить с оригиналом, исправить |
| PR03 | число оригинала не найдено в казахской версии | проверить: возможно, записано словом |
| PR04 | в казахской версии лишнее число | проверить: возможно, пересчёт единиц |
| PR05 | потеряно латинское имя или сокращение | вернуть или осознанно заменить |
| PR06 | в оригинале понятие глоссария, а выбранной казахской формы нет | решает автор (только с `--glossary`) |

Числа приводятся к одному виду: «6 мың» = «6000», «1,5 млрд» = «1 500 000 000», «12 желтоқсан» = «12 декабря» = «12.12.2025».
Числа, записанные словом, скрипт не сравнивает.

## 7. Задача E. Термины по узусу корпуса

Правило: **узус корпуса; международное слово — только там, где узус молчит**. Подготовьте файл групп, где ключ — группа корпуса,
а пути отсчитываются от самого файла:

```yaml
# groups.yaml
corporate:
  label: корпоративный узус
  files: [corpus/news_kk.txt, corpus/channel_kk.txt]
```

```bash
# сколько раз встречается каждая форма (контексты помогают отличить смыслы)
python3 tools/kk_attest.py --groups groups.yaml --terms data/terms_variants.yaml --context 3

# решения по парам; решения автора в глоссарии сохраняются
python3 tools/kk_usage.py --groups groups.yaml --group corporate --pairs data/term_pairs.yaml \
        --merge data/glossary.yaml --out data/glossary.yaml --tsv decisions.tsv
```

Свою пару добавьте в `data/term_pairs.yaml`: `a` — международная форма в казахском тексте, `b` — казахская, `re` — регулярное выражение
для строчных букв, `parity_ru` — как понятие выглядит в русском оригинале:

```yaml
- {key: well, ru: скважина, a: {label: скважина, re: "скважин\\w*"}, b: {label: ұңғыма, re: "ұңғыма\\w*"}, parity_ru: "скважин\\w*"}
```

Статусы записей: `usage` — одна форма не меньше 70% вхождений при десяти и больше; `silent` — вхождений меньше десяти, берётся международная форма;
`contested` — доли от 30 до 70%, решает автор. Чтобы закрепить своё решение, уберите `status` или напишите `status: author`: при `--merge`
такая запись не перезаписывается. Решения линтер применяет как предложения (`author_choice`).

**Корпус из двуязычного Telegram-канала.** В Telegram Desktop выберите «Экспорт истории чата» в формате JSON (файл `result.json`):

```bash
python3 tools/kk_pairs.py build result.json -o pairs.jsonl                 # пары «казахский пост — русский пост»
python3 tools/kk_pairs.py align pairs.jsonl -o candidates.tsv              # кандидаты в двуязычный глоссарий
python3 tools/kk_pairs.py consistency pairs.jsonl --glossary data/glossary.yaml \
        --term-pairs data/term_pairs.yaml -o consistency.tsv --write       # насколько переводы следуют глоссарию
```

`candidates.tsv` — статистика совместной встречаемости, а не словарь: вердикт по каждой паре выносит человек. `--write` записывает в глоссарий
поля `consistency` и `parity_check`; проверка PR06 включается только для записей, где согласованность не ниже 85%.

## 8. Частые проблемы

| Симптом | Что делать |
| --- | --- |
| `для YAML нужен PyYAML` или не находится `spylls` | `pip install -r requirements.txt` |
| «словарь не загружен» | путь к `--dict` пишется без расширения: `data/hunspell/kk_KZ`; рядом должны лежать `.aff` и `.dic` |
| «похоже на легаси-кодировку» | сначала прогоните текст через `kk_clean.py` |
| слишком много слов вне словаря | добавьте верные слова в `--whitelist`; словарь старый и о новых словах не знает |
| `apply.py` отдал находку автору: «цитата не уникальна» или «не найдена» | правьте вручную по полю `quote`; после правок текст и находки нужно сверять заново |
| латиница в казахском тексте не правится | так задумано: набор рассчитан на кириллицу, латинские слова не трогаются |
| текст в другой кодировке, не UTF-8 | перекодируйте: `iconv -f cp1251 -t utf-8 in.txt > out.txt` |

Ошибки и пожелания — в [Issues](https://github.com/bsakhanov/kk-redkollegiya/issues).
